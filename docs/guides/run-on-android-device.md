# Run BudgeDino on your Android phone (dev loop)

Checklist for the local dev loop on a physical phone (for example a Samsung S22) over USB. The server
runs on your Mac, the phone reaches it over Wi-Fi. No emulator: use the real device.

## Security (read first)

- This setup is for **development only**. The dev server listens on all network interfaces
  (`HOST=0.0.0.0`) so the phone can reach it, and the demo credentials are fixed and public
  (`demo@budgedino.test` with a known password and a TOTP secret from `.env.dev.example`).
- Use a **trusted Wi-Fi only** (not guest, café or office networks).
- **Stop the server when you are done** (`Ctrl+C`).
- **Never port-forward or otherwise expose it** to the internet, and never run it against real bank data.
- To keep it local-only, start it with `HOST=127.0.0.1 pnpm dev:server` (the phone then cannot reach it).

## One-time setup

- [ ] Docker (Docker Desktop or similar) running, for the dev database.
- [ ] Node 22 and pnpm via corepack: `corepack enable` (the repo pins pnpm; `.nvmrc` pins Node).
- [ ] JDK 17 (Temurin) and the Android SDK; set `ANDROID_HOME`, for example
      `export ANDROID_HOME=$HOME/Library/Android/sdk` and put `$ANDROID_HOME/platform-tools` on `PATH` (for `adb`).
- [ ] `mise trust` once in the repo so `.mise.toml` (java 17) is honoured. Without mise:
      `export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home`.
- [ ] `pnpm install`
- [ ] macOS firewall: System Settings > Network > Firewall. If it is on, allow incoming connections for
      Node, otherwise the phone cannot reach port 8080.
- [ ] Phone: Settings > About phone > Software information, tap **Build number** seven times, then
      Settings > Developer options > turn on **USB debugging**.
- [ ] Connect the phone by USB, accept the "Allow USB debugging" prompt on the phone.
- [ ] `adb devices` lists the phone with state `device` (not `unauthorized`).

## Every session

- [ ] `pnpm dev:db` starts Postgres on port 5433.
- [ ] `pnpm dev:seed -- --with-data` creates the demo household, a demo member, a connected demo bank
      with ~60 days of transactions and two budgets. It prints a one-time admin invite (`invite_token`).
      The values it prints (invite, demo password, TOTP secret) are dev-only.
- [ ] `pnpm dev:server` starts the API on `0.0.0.0:8080` with the demo bank (`fake` connector) enabled and
      prints a warning about the open interface. The dev master key in
      `.dev/master.key` is generated by whichever dev run comes first (`dev:seed` or `dev:server`); keep that file.
- [ ] Find your Mac's LAN IP: `ipconfig getifaddr en0` (Wi-Fi). Phone and Mac must be on the same Wi-Fi.
- [ ] Check from the phone's browser: `http://<lan-ip>:8080/api/v1/health` shows `{"ok":true,...}`.
- [ ] `pnpm mobile:android` regenerates the native project (`expo prebuild --clean`) and installs the
      development build on the phone. **The first build takes 5 to 10 minutes.** Later runs are faster.
- [ ] In the app enter `http://<lan-ip>:8080` as the server address and tap **Check**.
- [ ] Either **sign in** as `demo@budgedino.test` with the demo password and the code from the seed's
      `dev_totp_secret`, or **register** with the `invite_token` from the seed and add the TOTP secret
      shown in the app to your authenticator app, then confirm with its code.
- [ ] Home shows the Groceries and Eating out budgets with real numbers. Under Connections, "Add bank"
      offers **Demo bank**; connecting it shows a challenge you confirm.

Re-running `pnpm dev:seed -- --with-data` is safe: it creates nothing twice and prints a fresh invite.
The seeded transaction dates are fixed at the **first** run (relative to that day). To refresh them, wipe
the dev database and seed again: `docker compose -f docker-compose.dev.yml down -v`, then `pnpm dev:db`
and `pnpm dev:seed -- --with-data`.

## Maestro flows (optional)

Opt-in, never part of CI. The flows need a build that skips the app lock (the lock would block
`launchApp`), which only a **development** build started with `BUDGEDINO_E2E=1` does. The flag is read from the Metro
process env (not from prebuild), so stop any Metro already running on port 8081 first; release builds ignore
the switch (`__DEV__` is false).

```sh
# once (either works; see the Maestro docs)
curl -Ls "https://get.maestro.mobile.dev" | bash      # or: brew tap mobile-dev-inc/tap && brew install maestro
BUDGEDINO_E2E=1 pnpm mobile:android                   # build without the app lock
pnpm maestro:device
```

With the server running, the seed done and the phone attached, it runs `login`, `home` and
`connect-demo-bank` from `src/mobile/maestro` on the physical phone, deriving the login code from
`BUDGEDINO_DEV_TOTP_SECRET` (see `.env.dev.example`). Run it at most once per 30 seconds: a TOTP code can
only be used once. Restart Metro without `BUDGEDINO_E2E=1` (`pnpm --filter ./src/mobile start`, or a normal `pnpm mobile:android`) to restore the app lock.

## Troubleshooting

- **`adb devices` shows `unauthorized`:** unlock the phone, accept the USB debugging prompt (tick "always
  allow"); if it never appears, revoke USB debugging authorisations in Developer options and replug.
- **Phone cannot reach the server:** check the macOS firewall step above, that Wi-Fi does not isolate
  clients (guest networks), and that the IP did not change (re-check `ipconfig getifaddr en0`).
- **App says the server is unreachable although the browser works:** use `http://` (not `https://`) and
  no trailing path; the development build allows cleartext, release builds do not.
- **Metro / app does not load JavaScript:** the phone must be on the same Wi-Fi as the Mac; `pnpm
mobile:android` starts Metro, so keep that terminal open. `adb reverse tcp:8081 tcp:8081` also works over USB.
- **Build fails with a Java error:** `java -version` must report 17; run `mise trust` or set `JAVA_HOME`.
- **`dev:server` says the master key or database is wrong:** the dev database was created with another
  `.dev/master.key`. Wipe it: `docker compose -f docker-compose.dev.yml down -v`, then `pnpm dev:db`.
- **Login with the demo account fails with an invalid code:** the TOTP secret is fixed when the seed first
  creates the member. If you changed `BUDGEDINO_DEV_TOTP_SECRET` afterwards, wipe the database (see above).
